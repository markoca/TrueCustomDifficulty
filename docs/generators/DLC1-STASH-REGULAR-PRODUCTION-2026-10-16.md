# DLC1 regular stash control coverage — implementation contract (2026-10-16)

## CURRENT implementation boundary

Existing Stashes sliders/graphs now control ordinary generic source items through two independent sources in the base game and enabled DLC1. **Base coverage is unchanged:** the 803 approved no-clue base SmartLoot actors and the three existing production ItemGenerator clone families. **DLC1 expansion:** exactly 112 new no-clue ordinary `WorldMap_WP` actors with audited generic-only item sources are eligible for the *SmartLoot* SID replacement in the **DLC actor file**, `DLCGameData/DLC1/SpawnActorPrototypes.cfg`. These 112 use the same 13 base SmartLoot prototype families / 991 source item rows; the cloned `TCD_*` source prototypes continue to live only in `GameData/StashPrototypes.cfg`. No shared vanilla prototype is changed globally.

**The 112 DLC1 actors are not a count of new guaranteed-medical stash drops.** Their originally authored list order and other source bindings stay unchanged. The 112 consist of 24 Cheap, 59 Common Var1, 19 Rare, 6 CheapNoFresh and 4 SmartLoot-only actors. The strict exact actor roster is embedded as `src/TrueCustomDifficulty/Data/dlc1-stash-eligible-actor-manifest.csv`. The source audit `docs/generators/dlc1-stash-generic-actors.csv` remains a non-authorizing inventory of **196** DLC1 ItemContainers. Clue, quest/test, mixed/special, MQ06, CNPP, named weapons and blueprint contexts are **excluded** from the new DLC SmartLoot allowlist. This is safety before maximum numerical coverage.

## Preserved exclusions

Never broaden the 112-row actor list by naming pattern or substring. The DLC1 archive has 196 containers (179 main-world) and 175 with some generic source; **175 is not a safe patch allowlist**. Actors in the other 84 slots have mixed special/quest content, DLC-specific mission uses, or no resolved generic source. Some can have generic items in parallel with unique rewards, but no new logic here touches those unreviewed paths.

Nothing here touches item generators used by NPC corpses, destructible crates, dialogue gifts, one-time pickups, stash clue variables, or source-authored unique weapon/armor paths. The base 28 named clues and 71 excluded Blueprint/Unique/Quest actors remain outside the 803 base SmartLoot actors. DLC1 remains fully disabled when `hasDlc1=false`. All existing `loot.*` IDs, factory presets and locked five-graph Stashes visual design stay identical; baseline Vanilla/Base values are not emphasized.


## 2026-10-16 — Linux Wine LootSpecial contract: fixed non-Loot baseline

The Windows-targeted test now builds successfully on Linux after `tests/Directory.Build.props`, but the first `Novice / vanilla` scenario exposed a **test expectation defect**, not evidence of unwanted Stashes output: `survival.sleepHealthRestore` deliberately starts at **100 HP**, compared with a source-authored **300 HP** (two legitimate leaves in `GameData/EffectPrototypes.cfg`: `SleepHealthRestore.ValueMin` and `ValueMax`). The slider permits only 0–200 HP; resetting it to 300 in the test would be invalid and would change the source contract. The LootSpecialGeneratorsContract regression now explicitly tests the **two exact 100-HP leaves** and counts that fixed-default parameter in each Loot-only scenario; it rejects any additional non-Loot modifications. No production writer, game defaults or Stashes logic changed in this correction. Removed an unused test-only `MainFile` constant that raised `CS0414`.

**Verification:** `dotnet build tests/LootSpecialGeneratorsContract/LootSpecialGeneratorsContract.csproj -c Release -r win-x64` followed by `./tests/run-wine.sh LootSpecialGeneratorsContract`. This was previously confirmed to compile on the user's Linux machine; the corrected Wine contract still requires rerunning. Do not treat Vulkan/RADV's diagnostic warning as this CFG validation error.
