# Generator Domain Audit Matrix

This is the living control-safety table for generator-backed gameplay systems. It is populated domain by domain **before** any new generator-backed UI control is implemented.

## Hard control-candidate exclusions

As of v0.1.80, **test/debug-only**, **Prologue-specific**, and **one-time/story-scripted** generator targets are hard-excluded from generic UI/control design even when they are technically isolated or 1:1. The exhaustive SID-level register is `generators/control-candidate-exclusions.csv`; rationale and highlighted cases are in `generators/CONTROL-CANDIDATE-EXCLUSIONS.md`.

A reusable production generator is not excluded solely because one incidental consumer is a test or Prologue actor. Exclusion applies when the **target itself** is specific to an excluded context.

As of v0.1.81, structural safety and UI suitability are tracked separately. `generators/CONTROL-CANDIDATE-TRIAGE.md` is the authoritative post-audit shortlist/defer decision layer; passing this matrix does not automatically make a generator a player-facing control.

Status meanings:

- **DEEP AUDITED** — exact pools/consumers/items/gates and blast radius have been reviewed.
- **MAPPED** — present in the v0.1.66 topology/group catalogs, but not yet deep-audited for control design.
- **EXCLUDE BY POLICY** — intentionally not a generic tuning target (for example named/scripted NPCs or quests).
