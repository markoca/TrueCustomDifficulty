# Deep CFG Audit — Phase 2: direct CFG node-path validation (2026-10-09)

**Scope:** follow-up to [Phase 1](DEEP-CFG-AUDIT-2026-10-09.md), focused on structural path correctness in the production direct BPatch writer and source values in the user-provided vanilla GameData/DLC1 archives.

## Verified high-impact defect (FIXED in the same changeset)

All **16** direct Mutant Health `MaxHP` edit points had the **correct source numeric values and prototype SIDs**, but their writer `nodePath` was **empty**. The actual decoded `GameData/ObjPrototypes.cfg` stores these values under a nested **`VitalParams : struct.begin`** node:

```cfg
Bloodsucker : struct.begin
    ...
    VitalParams : struct.begin
        MaxHP = 500
    struct.end
struct.end
```

The production writer uses `PatchDocument.GetOrAddNode(prototype, point.NodePath).SetAssignment(key, value)`. An empty path therefore generates a **root-level** `MaxHP` assignment instead of patching the existing `VitalParams.MaxHP`. Raw-value parity alone had incorrectly appeared to validate this mapping in Phase 1. This is a genuine source-to-writer structural issue, not a presentation or runtime-simulation discrepancy.

**Correction applied:**
- All 16 concrete `combat.mutantHealth.*` writer entries now have `nodePath: ["VitalParams"]`, `key: "MaxHP"` and retain their precise source values, prototype IDs, and `scale` operation.
- All **14** corresponding catalog entries now use `targets[].path: "VitalParams.MaxHP"`. No parameter IDs, sliders, preset values, MaxHP constants or ability cooldown mappings changed.
- `tools/audit_cfg_dump_provenance.py` now rejects a root-level `MaxHP` route and requires the matching nested catalog path.
- `tools/audit_project_consistency.py` locks the corrected writer and catalog structure.
- The standalone structural-source tool `tools/audit_cfg_source_values.py` checks **all direct writer edit points** using the actual decoded CFG tree, reporting missing prototypes, missing nested nodes, missing fields, lexically differing but numerically equivalent literals, and real raw-value mismatches. It can emit a JSON report and fail in `--strict` mode. It deliberately does not auto-rewrite inferred inherited CFG fields.

## Evidence checked independently

1. Both previously provided source archives were present. SHA-256 identities remain those in Phase 1.
2. All **16 Mutant Health prototypes** were located by exact name in the **base-game** `ObjPrototypes.cfg`. Each has exactly one nested `VitalParams.MaxHP` whose value matches the production baseline. A structural probe using `nodePath=[]` produced **`missing_key`** for `Blinddog`; the corrected `["VitalParams"]` probe produced **16/16 exact matches** across all original and six newly added mutant targets.
3. A standalone CFG parser was exercised against **all 13 direct-writer input files** in both source ZIPs. All 13 decoded successfully into balanced top-level and nested `struct.begin / struct.end` trees. It ignores `//` comments, including commentary containing `=`, to avoid false duplicate property failures (encountered in `CoreVariables.cfg`).
4. The production C# `PatchDocument.AddAssignment` / `GetOrAddNode` implementation was inspected to confirm that `nodePath` defines the actual nested BPatch output hierarchy rather than a human-readable hint.

These checks confirm the 16 corrected source paths. **They do not establish that every other edit point is already safe.** For the **1,208 other direct writer edit points**, structural/source parity needs the exhaustive JSON report generated by the new tool (the full baseline was available via the GitHub connector, but not mounted in the same local process as the decoded archives). The new tool enables that verification on the user's local checkout. **Do not describe this phase as all 1,224 direct fields validated.**

### Execute the exhaustive input-source audit

Run after `git pull`, pointing to matching decoded source archives:

```bash
python tools/audit_cfg_source_values.py \
  --base-zip "$HOME/s2tools/cfg_dump/STALKER2-GameData-CFG.zip" \
  --dlc1-zip "$HOME/s2tools/cfg_dump/STALKER2-DLC1-CFG.zip" \
  --out ./audit/cfg-source-values.json --strict
```

The script reports structural findings without silently treating inheritance as failure or success. For any non-exact source, first identify whether it is a genuinely absent field, inherited field, a reference-key alias, or a game-update drift. Only correct **evidence-backed** mappings. Keep negative-space safety: do not expand edits into sibling NPC/quest bosses, runtime lairs, or unused DLC records merely to satisfy counts.
